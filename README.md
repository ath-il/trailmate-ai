# TrailMate AI

An offline-first outdoor mission companion that runs a real open-weight language
model **locally in your browser** using [WebLLM](https://github.com/mlc-ai/web-llm)
and WebGPU. No backend, no API keys, no cloud AI, no external database. Your
prompts, missions, and journal entries never leave your device.

Built for the **Hacktoberfest "Touch Grass" challenge**.

**Live demo:** https://trailmate-ai-ypcf.onrender.com (deployed on Render)

> **First visit needs the internet.** The website is a static app, but the local
> AI model (a few hundred MB) is downloaded **once** from the open model CDN and
> cached by the browser. After that first download TrailMate works fully offline.
> If the model has already been supplied/cached locally, no internet is needed at
> all. The ordinary website build **never bundles** the model weights.

---

## What it does

- **Home** — choose available time (5/15/30/60 min), difficulty
  (Easy/Moderate/Adventurous), environment (Garden/Park/Neighborhood/Anywhere
  safe) and activity (Walking/Nature Observation/Gardening/Surprise Me), then tap
  **Find My Mission**.
- **Mission generator** — produces a mission with a title, description, 3–5
  practical steps, duration, difficulty, a checklist, a nature observation
  challenge, and a reflection question. Generated by the local model when
  available, otherwise from bundled hand-authored missions.
- **Mission timer** — start / pause / resume / reset countdown plus an
  interactive checklist and a **Complete Mission** button.
- **Completion** — celebration screen, `+10` nature points, saved date and
  reflection, and protection against awarding points twice for the same mission.
- **Nature journal** — completed missions and reflections, total points, and the
  current daily streak. Persisted in **IndexedDB**, so it survives closing and
  reopening the browser.
- **Offline experience** — production service worker (Vite PWA / Workbox) caches
  the whole app shell. Online/Offline and AI Ready/AI Unavailable indicators are
  always visible, and bundled fallback missions keep the app useful without AI.

## Technology

| Area        | Choice |
| ----------- | ------ |
| UI          | React 18 + TypeScript + Vite 5 |
| Styling     | Tailwind CSS 3 |
| Local AI    | `@mlc-ai/web-llm` running on WebGPU in a Web Worker |
| Persistence | IndexedDB (`idb`) for the journal, `localStorage` for preferences |
| Offline     | `vite-plugin-pwa` (Workbox) service worker |
| Icons       | Generated locally by `scripts/gen-icons.mjs` (no remote assets) |

There are **no runtime network dependencies** for the app itself. No remote
fonts, images, APIs, or databases.

### Default local model: Gemma 3 1B

`gemma3-1b-it-q4f16_1-MLC` (~711 MB VRAM) — **Google's open-weight Gemma 3**,
run entirely on-device through WebLLM. Because the weights are open and run
locally, the app keeps working with no internet, no API keys, and no
per-request cost. It is a `low_resource` model that does **not** require the
WebGPU `shader-f16` feature, so it works on the widest range of devices. Other
open-weight 1B–3B models (`Llama-3.2-1B`, `Qwen2.5-1.5B`, `Qwen2.5-3B`) can be
selected in **Settings**. Model identifiers come from WebLLM's
`prebuiltAppConfig` and were verified against `@mlc-ai/web-llm@0.2.86`.

## Getting started (online, one time)

```bash
npm install
npm run dev      # http://localhost:5173
```

Then, in the app:

1. Open **Settings** and confirm the status shows your device supports WebGPU.
2. Tap **Prepare local AI** (or use the button on **Home**). The model weights
   download once (a few hundred MB) and show live progress.
3. Wait for **AI Ready**. This first run needs an internet connection so the
   model can be downloaded.

### Production build & verification

```bash
npm run build    # type-check + production build into dist/
npm run preview  # serve the production build at http://localhost:4173
npm run smoke    # serve dist/ and assert the shell, SW, manifest, icons, chunks
```

`npm run smoke` boots the built site from `dist/` with a small zero-dependency
Node server and checks that the app shell, `manifest.webmanifest`, service
worker, icons, and lazy JS/CSS chunks all resolve — i.e. everything needed for
an offline install. It exits non-zero on any failure.

Open the preview in a WebGPU-capable browser, load the model once, and the app is
then usable offline.

## Making it work offline

1. **First load (online):** the service worker installs and precaches the app
   shell (HTML, CSS, JS, the lazy WebLLM chunk, the worker, icons).
2. **Load the model once (online):** WebLLM downloads the weights and stores them
   in the browser Cache API. This is WebLLM's own caching mechanism, separate
   from the service worker.
3. **Go offline:** reload. The app shell loads from the service worker, the model
   loads from the WebLLM cache, and inference runs entirely on-device.

To verify: load everything once, then use your browser devtools "Offline" mode
(or disconnect) and reload. Navigation, journal, timer, and mission generation
continue to work.

## Deploying (static hosting)

TrailMate AI is a static front end: the build produces plain files in `dist/`
and there is no server component. Any static host works. Configs are committed
for **Render**, **Vercel**, and **Netlify**.

**Host requirements:** serve over HTTPS (service workers and WebGPU need a
secure context; `localhost` counts as secure) and never cache `sw.js`.

### Render (Best Use of Render)

A `render.yaml` Blueprint is included.

1. Push the repo to GitHub/GitLab.
2. In Render: **New + → Blueprint**, then pick the repo.
3. Render runs `npm ci && npm run build`, publishes `./dist`, and applies the
   SPA rewrite and cache headers from the Blueprint automatically.

This project's live deployment: **https://trailmate-ai-ypcf.onrender.com**

### Vercel

`vercel.json` is included (SPA rewrite + service-worker cache headers).

1. `npm i -g vercel` (or use the dashboard).
2. From the project folder run `vercel` and accept the detected Vite settings
   (build `npm run build`, output `dist`).
3. `vercel --prod` to ship.

### Netlify

`netlify.toml` is included (build command, publish dir, SPA redirect, headers).

1. Connect the repo in Netlify, or run `npx netlify deploy --build --prod`.
2. Netlify uses the committed `netlify.toml`; no dashboard changes needed.

### Any other static host

Run `npm run build` and upload `dist/`. Add a catch-all rewrite to
`/index.html`, and a `Cache-Control: no-cache` header for `sw.js` and
`registerSW.js`.

## Honest limitations

Offline support is implemented with the standard browser primitives (service
worker + Cache API), but true offline operation depends on the browser and
device:

- **WebGPU is required for local AI.** Without it (many Safari/Firefox versions,
  some Linux/VM setups, older GPUs), the app shows **AI Unavailable** and uses
  bundled offline missions instead. It never pretends those are AI-generated.
- **Cache eviction.** Browsers may evict Cache API / IndexedDB storage under
  storage pressure, or if the user clears site data. If the model is evicted, it
  must be downloaded again (Settings shows whether it is cached).
- **Storage quota.** The model needs several hundred MB of available browser
  storage. Private/incognito windows may not persist it.
- **First paint vs. AI.** The bundled fallback missions work the instant the app
  loads. Local AI generation only works after the model has been downloaded.
- **Service worker scope.** Offline app-shell caching applies to the origin the
  build is served from; serving `dist/` over `http://localhost` is fine, but
  opening `index.html` directly via `file://` will **not** register the service
  worker.
- Different browsers implement WebGPU and storage differently, so behavior can
  vary. This project was verified to type-check and build; browser-level offline
  testing was done manually and may differ on your machine.

If local AI cannot run for any reason, TrailMate AI keeps working with the 18
bundled missions and clearly labels them as **Offline mission**.

## Privacy

Everything happens client-side. Mission prompts, journal entries, reflections,
and preferences are only ever stored in your browser's IndexedDB and
`localStorage`. Nothing is uploaded anywhere.
